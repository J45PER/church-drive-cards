# Clive on the Home Assistant side

Clive is the preferred Assist pipeline ("Home Assistant Cloud"): wake word `hey_jarvis` (openWakeWord, local), Home Assistant Cloud speech-to-text and text-to-speech, and the Claude conversation agent (`conversation.claude_conversation`, Haiku 4.5, the Anthropic integration with the household's own API key). `prefer_local_intents` is on, so simple commands never reach Claude.

What Clive can reach is decided by **voice assistant exposure** (Settings > Voice assistants > Expose), which is global, not per person. Everything below changes only `conversation`; Alexa and Google exposure were left alone.

Naming: scripts and code are named `clive_*` (the live scripts were renamed from `jarvis_*` on 2026-10-21; same configs, checked by config hash). The old name survives only in the wake word model `hey_jarvis` (a model name, not ours to rename) and in old log ids that must never change. Nothing in code should hard-code the assistant's name: use `assistantName` / the house's name in the app, and generic names (`Assistant*`) for code identifiers.

The `clive-*.yaml` files here are copies of the live scripts. Edit them in Home Assistant and re-export, or paste a file back to restore it.

## Deliberately not exposed

- **Sirens** (5 switches, 5 siren entities) and the **alarm panel** (no voice disarm).
- **Camera motion-detection switches** (Driveway, Entrance, Garden, Living Room, Front Doorbell): they are motion on/off switches.
- **Energy and cost data** (Octopus electricity and gas, Zappi energy and grid power): admin-only, and exposure is global.
- **TVs and PCs** (`media_player.*`): until a room-aware tool exists. The app has no room, so "only the device in the same room" cannot be enforced yet. Needs a custom LLM API in this integration that reads the satellite's area. Build it with the first satellite.
- **`select.zappi_charge_mode`**: only reachable through `clive_zappi_charge`.
- **The car** (Vauxhall Astra): read-only sensors only (battery, range, fuel, fuel range, plugged, charging, charging end, mileage, service due, doors, boot). No buttons, switches or numbers, so no lock, horn or preconditioning.
- **Hue scenes** (133) and the integration's "Church Drive" working scenes: Clive uses the library through `clive_apply_scene` instead.
- Gregg's own vacuum entity, Find Robot switch, and the Ring chime switches.

## The Fast-charge confirmation

`clive_zappi_charge` with mode Fast at a rate that is not cheap does not start. It stamps `input_datetime.zappi_fast_charge_confirm_asked`, and returns `needs_confirmation` with the current and cheapest rates. Clive must ask and wait. A repeat call with `confirm_expensive: true` only counts if it arrives **5 to 300 seconds** after that stamp. The first version trusted the flag, and Clive set it himself on the first call, so the window is enforced in the script.

The helper is an `input_datetime` (date and time), initial `2000-01-01 00:00:00`.

## Timed heating and fan

"Bedroom fan on max for 2 hours", "heating on for an hour". Entirely in Home Assistant, so it works from the phone, watch and any voice device without an app release.

- **Two scripts.** `clive_timed_control` (exposed) does the change and returns at once, so Clive can answer; it starts `clive_timed_revert` (not exposed), which waits for the timer to finish or be cancelled and then puts the device back. A script that waited itself would keep Clive's tool call open for the whole two hours.
- **Put back from a snapshot.** Before the change it takes a `scene.create` snapshot of the climate or fan, and the revert is `scene.turn_on` of that snapshot, so heating that was off goes back to off, and a fan that was off goes back to off.
- **Timers.** One `timer` helper per target (`timer.clive_heating_downstairs`, `timer.clive_heating_upstairs`, `timer.clive_bedroom_fan`) holds the end time and stops a second run starting on the same target (the result is `already_running`). "Cancel the heating" is `command: cancel`, which cancels the timer and so triggers the put-back. The revert also has its own timeout (length plus 10 minutes).
- **Heating setpoint.** Always the higher of the middle of the room's comfort range and 2°C above the current temperature, rounded up to 0.5, never above the thermostat's maximum. It sets the mode to heat.
- **Fan speed.** Max (100%) unless asked for Low (33%) or Medium (67%).
- **The warning.** Heating when the room is already at or above the bottom of its comfort range, or the fan when it is already at or below the top, does **not** start. The result is `warning` with the temperature and the range, and Clive must tell the person and wait for a yes. The repeat with `confirm_unneeded` only counts 5 to 300 seconds after the warning, for the same target, and once (`input_datetime.clive_timed_warning_asked` plus `input_text.clive_timed_warning_target`, cleared on a start). The first version stamped no target, so a warning for one device let a different one through.
- **Comfort ranges** are in the script's `cfg` block, copied from the card room types (`CZ_TYPES` in `src/climate-zone-card.js`): downstairs 19 to 22 (living room), upstairs 16 to 20 and the bedroom fan 16 to 20 (bedroom). Change them in the script if a room's range changes. To add a device, add an entry to `cfg`, a timer helper and the option to the `target` field.
- **Limit:** the waiting lives in a running script, so a Home Assistant restart during a timed run loses the put-back (the timer survives, nothing reacts to it). The thermostat's own setpoint would stay at the timed value until someone changes it.

## Keeping the climate comfortable (Clive runs the heating)

A background job, no voice and no app. Clive is responsible for the automatic on and off of the heating. Every 10 minutes the automation `Clive: keep the climate comfortable` runs `clive_climate_zone` for Downstairs and Upstairs (the only two thermostats, both Nest, heat or off with an eco preset). **There is no air conditioning in Home Assistant**, so only heating exists; cooling would be added to the same script when there is something to cool with.

- **Adjusts the target only (2026-10-24).** He never turns the heating on, off or to eco himself: a zone that is off, or on eco, is left exactly as the person set it. He only changes the target of a zone that is already heating (mode heat, preset none).
- **Comfort ranges and slowness (2026-10-24).** Downstairs 18 to 21°C, upstairs 15 to 19°C (each 1°C lower than before; the timed service uses the same). Cold: only when the room is more than 1.5°C below the bottom of the range (downstairs below 16.5, upstairs below 13.5) and the target is less than 1°C above the room, and then the target is raised to the middle of the range. Too hot: only at 1°C or more above the top (downstairs 22, upstairs 20), and only if it is heating or the target is above the range, and then the target is lowered to the middle. Cooling would follow the same rule if it were ever added (no air conditioning exists in Home Assistant yet). At least 30 minutes between his own changes. The bedroom fan's range and the app's room-type colour ranges were not changed.
- **Per-zone switch.** `input_boolean.clive_climate_downstairs_auto` and `..._upstairs_auto` (Clive controlled when on, Manual when off; in the app's Settings, one row per zone) replace the earlier house-wide switch (deleted). With a zone's switch off the zone script decides `skip_disabled`, spots no manual changes, starts no pauses and says nothing. The prompt still says the adjusting can be switched off "for the whole house", which is no longer exact.
- **Steps aside** while a timed run (`clive_timed_control`) is going on that zone, and for 3 minutes after it.
- **If somebody changes the thermostat** he stops adjusting that zone (a pause) for `input_number.clive_climate_pause_minutes` (120 unless changed; the pause is per zone). A change counts as by hand when it is a change to the mode, preset or target that did not come from a Home Assistant script or automation (the dial, the Nest or Google Home app, a dashboard or Assist by voice): `Clive: spot a manual heating change` hands it to the zone script, which ignores it inside 3 minutes of Clive's own last action (the Nest echoes late and moves its own target when it leaves eco). The 10 minute check also notices a mode or preset that is not what he last set. Changes by the Nest itself (its own away/eco handling) look the same, so they pause him too.
- **Telling people.** When he pauses: a push notification (`church_drive.notify`, kind `clive_actions`, tag `church-drive-clive-paused-<zone>`: "Downstairs heating set by hand ... Clive will take over again at 16:42 (120 minutes)") and a persistent notification in Home Assistant (`clive-climate-<zone>`) saying the same. A **Resume Clive** button comes with the push notification for the Home Assistant app (`CD_clive_resume`, done by `notice_actions.py`, which calls `clive_climate_control`) and an **Open Climate** button for both apps. When the pause ends (`Clive: take over again when a pause ends`, at the time in `input_datetime.clive_climate_<zone>_resume`) or someone resumes him, he says "Clive is back in charge of ..." and dismisses the persistent notification. Raising a cold room's target is also a push notification and a logbook entry under "Clive".
- **Resuming, pausing, asking.** `clive_climate_control` (exposed to Assist): command `resume` (now), `pause` (minutes, for a zone or all) or `status` (temperature, mode, whether he is in charge or paused until when, and what he last did and why). So "Clive, resume the heating", "leave the heating alone for 3 hours" and "why is the heating off?" work in the app, on the watch and from any voice device. The same script can be a dashboard button.
- **What he is holding** is in `input_text.clive_climate_<zone>_note` and what he last set (to tell his own changes from a person's) in `_expect`, as JSON `{m, p, t, hot}`; `_when` is when he last acted; `_resume` is the end of a pause (2000-01-01 means none).
- **Never fights a person**, and a person's change is never undone: after a pause he only acts if the room needs it.
- **Not a notification for every little thing.** Every action is in the logbook, but a push is sent only for a raised target, at most one push per zone every 2 hours (`input_datetime.clive_climate_<zone>_notified`). Lowering the target is silent. A pause and the end of one always tell people (they are the person's own doing). The tag per zone replaces the previous notification instead of stacking.
- **Notification kind.** `clive_actions` ("Clive adjusted the house", House group, admins by default) is added by the integration (`kinds.py`), so it appears in Manager after the next integration release and Home Assistant restart; until then nobody is ticked and nothing is sent (the persistent notification and the logbook still are).
- **In the Church Drive app (0.48.0).** The Home page shows a "Heating set by hand" reminder below the to-do highlights while any zone is paused (read from `input_datetime.clive_climate_<zone>_resume`, nothing else to set up): which zones, when he takes over again, and a **Resume** button (`script.clive_climate_control` with command resume). The Resume Clive notification button (`clive_resume` in `NoticeButton.kt`) does it without opening the app. Notifications of kind `clive_actions` carry the assistant's mark as the small status-bar icon and a colour copy as the large icon; every other kind keeps the Manager's icon. The Home Assistant app's copy of a notification has Resume Clive as well.
- **Testing.** `clive_climate_zone` takes `dry_run` (report the decision, change nothing), `pretend_temperature` and `by_hand`. A real run with a pretend temperature changes the thermostat, and one inside 30 minutes of an action is skipped (reset `_when` to 2000-01-01 to test twice).

## Tuning Clive from a session (instructions and model settings)

Claude can read and change Clive's instructions and the Claude model settings through Home Assistant, with no copy and paste: the Anthropic integration (`entry_id` 01M376K2WJGE6N1C80RF6D40SE) has a `conversation` subentry (`01M376K2WJXBAQ5MWA048ZS9DZ`, "Claude conversation") whose fields are the ones on its Configure page. Read them with `ha_get_integration(entry_id, include_subentry_schema=True, subentry_type="conversation", subentry_id=...)` (the prompt and the Assist/tool choice) and `include_diagnostics=True` (everything else; the prompt shows as redacted there). Change them with `ha_config_set_helper(helper_type="config_subentry", entry_id=..., subentry_type="conversation", subentry_id=..., config={...})`: it is a patch, so only the fields given change (checked: sending `recommended` and `max_tokens` alone left everything else as it was). Always send `recommended: false` or the model settings are reset to the recommended ones.

How it is done:
- The instructions are edited in `clive-prompt.md` first, then sent as `prompt`, so git always has the previous version. The live prompt and that file are meant to be identical (they were when this was set up).
- A change to a model setting is noted in the commit message with the old value, and checked afterwards by reading the settings back and by the timings the app shows in Settings (speech to text, Claude, tools, text to speech).
- Never tick "HA-MCP Server (tool search)" for Clive: it would give him every Home Assistant tool and bypass the exposure list that keeps the alarm, sirens and TVs out of reach.
- The AI Task entity (`ai_task_data` subentry) is a separate thing and is left alone.

Settings on 2026-10-23 before the first tuning (the baseline to go back to; the same day `thinking_budget` was set to 0 and `max_tokens` to 1000 for speed, and the instructions got the "How long to talk" paragraph):

| Setting | Value |
|---|---|
| `chat_model` | `claude-haiku-4-5` |
| `max_tokens` | 3000 |
| `thinking_budget` | 1024 |
| `prompt_caching` | `prompt` |
| `web_search` / `web_search_max_uses` | on / 5 |
| `web_fetch`, `code_execution`, `user_location` | off |
| `llm_hass_api` | `["assist"]` |
| `recommended` | false |

Plain commands never reach Claude at all: the Assist pipeline has `prefer_local_intents` on. ## Gotchas learned the hard way

- **Check state after a write, not the spoken reply.** Clive says "Done" whenever a script runs without error. A template condition that returned a non-boolean string (a time) was silently false.
- **Script `variables` re-sort alphabetically when saved** through the API, so a variable that reads another declared "later" breaks. Use separate `variables` steps, or one template.
- **Datetimes and lists of datetimes become strings between variables.** Do date maths in a single template (as the Zappi smart charge automation does).
- **A script can return data to Clive** with `stop` and `response_variable`; the result is shown to him as a tool result.
- **"Waiting for EV" means the car IS plugged in** but not asking to charge (usually full). Only "EV Disconnected" is unplugged.
- **Octopus Go publishes tomorrow's cheap window only after midnight**, so tomorrow's rates hold just one slot. `clive_zappi_info` projects the 00:30 to 05:30 window from today's pattern and says so.
- **Battery-low sensors come from Battery Notes**, not the phone app, so phones are excluded by device (`device_id` of `mobile_app` entities).
- **Don't let him overclaim.** The safety check says what it did not check (doors, windows, locks, the burglar alarm).

## Who is asking, web search, pictures (prompt additions)

Each person signs in to the app with their own Home Assistant user, so the conversation agent can know who is asking: the prompt is a template and `user_name` is the signed-in user's name. Add this to the prompt (Settings > Devices & services > Claude > Claude conversation), after "Where you are":

```
{% if user_name %}The person talking to you is {{ user_name }}. When they say "my", "me" or "I", they mean {{ user_name }}: for their tasks or to-dos read the list called "Priorities" followed by their first name, and also the shared priorities list, and never ask which person they are. {% else %}You do not know who is talking, because this device has nobody signed in, so for anything personal such as to-dos ask which of Die Ann, Hayley, Ian or Jamie it is for. {% endif %}
```

Web search: the Claude agent already searches the web (sport scores and fixtures, news, facts), as the prompt asks. Check that "Allow web search" is on in the same settings page.

Pictures and links: add to the prompt, after "What you can see and do":

```
When a picture or web page would genuinely help (what something looks like, a recipe, a match report) and a web search gave you a real https address, call the show on screen script as well as answering aloud. Your spoken answer must make sense without it, because many devices have no screen. Never read a web address aloud.
```

Cards: the full, current prompt (with a mandatory card paragraph, and the order of speaking and calling scripts that Home Assistant needs) is in [clive-prompt.md](clive-prompt.md). Use that, not a paragraph added to an old prompt.

Screens are decided case by case: the Church Drive Android app listens for `church_drive_assistant_show` and shows it to the person it is for. A satellite with a display needs its own listener that filters on the event's `context.user_id` or its own device; satellites without one need nothing.
